Run `powershell -ExecutionPolicy Bypass -File Tests\Run-StressRegression.ps1` from the repository root on Windows with .NET Framework installed.

The harness compiles the production `StressProcessor`, `OnStrikePenalty`, and `SnacksRosterResource` source against deterministic KSP/Unity substitutes. It checks independent daily timers for loaded and unloaded vessels, timer persistence and legacy saves, recovery with overlapping conditions, crew boarding, multiple-day catch-up, restored resource identity, and updates without a vessel at KSC. It does not verify KSP's actual experience effects, Unity lifecycle, or background converter execution.

Build output goes to `Snacks/obj/StressValidation`. No game files or configs are changed.

Run `powershell -ExecutionPolicy Bypass -File Tests\Run-BackgroundRegression.ps1` to build without post-build deployment and test the compiled mod against the installed KSP assemblies. The default paths use KSPDev and Visual Studio 18 Professional. This suite checks the production base processor's per-vessel timers and save migration, event catch-up and persistence, snapshot resource routing and locks, transient failure retries, minimum crew requirements, and output capacity/DumpExcess behavior. It does not start KSP or verify Unity lifecycle and CommNet behavior in a running game.

It also checks multi-tank resource conservation and overflow accounting, handoff timestamp clipping and persistence, exact yield boundaries and fractional progress, paused yield time, chronological catch-up steps, continuous generation with a battery smaller than an hour's demand, named production-result checks, and cleanup after iterator failures. The timeline test substitutes vessel discovery and event execution; the power test runs the production converter stepping method with deterministic electricity policy. Actual unload event delivery, live loaded converters, and CommNet still require an in-game check.

Exemption checks cover exact first/full-name matching, case and whitespace handling, clearing and direct API edits, tracked crew flag synchronization, scenario load with current/legacy keys, loaded/unloaded mixed-crew consumption, all-exempt vessels, catch-up cycles, and missed-meal accounting. The Stress harness also verifies exemption handling for threshold notifications, strike penalties, and vessel loading. The loaded crew test supplies KSP's cached crew list; actual window interaction and crew registration still require an in-game check.

Meal multiplier checks use the production Snacks processor with deterministic resource access and outcome recording. They cover normal/fractional/invalid values, save persistence and old-save defaults, loaded/unloaded catch-up, individual shortages and counters, Soil from actual consumption, exemption precedence, vessel/manifest/anonymous-count estimates, EVA portions and pack sizing, and loaded/unloaded EVA resource estimates. Actual snapshot withdrawals are also checked across multiple unlocked tanks and fractional boundaries. Native loaded resource routing, EVA pack transfer, and the Space Center GUI still need an in-game check. Pass `-Configuration Release` to validate the release build before deployment.

Estimate refresh checks verify replacement of queued jobs for the same vessel, rejection of obsolete completions, publication of the current result, and clearing results when stopped. Unity coroutine cancellation is verified by compilation and still requires in-game coverage.

PR review checks extend the compiled background suite to real simulator worker tracking, idle sleeping, cancellation/reuse, processing new jobs, and stopping/joining workers. Run `Tests\Run-PrUtilityRegression.ps1` for isolated dynamic calendar and localization tests, and run `Tests\Validate-PrConfigs.py` with Python to check the authoritative KSPDev catalogs/configs without changing them. These tests do not validate live inventory/construction or translated GUI layout.

Calendar policy checks in the compiled background suite use different solar/calendar day lengths and verify solar-day processing and exact one-day nap seconds, calendar-based elapsed-duration formatting, unchanged fixed-hour naps, and retained minutes/seconds below an hour.
